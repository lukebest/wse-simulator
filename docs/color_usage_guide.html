核心结论：TDM 还是 Trigger？

既不是固定时隙 TDM 轮转，也不是「全芯片同一时刻只有一条 color 活着」。

链路上是 就绪色按需时分仲裁（Router RR/priority）；计算上是 事件触发激活 + Picker 选色起任务（Active/Block + base+color×4）。

两层机制概览

  • 每 color：独立 Data Queue（默认 2 entries/color）+ 静态 Dest 661 多播表
  • 每 color 单活跃输入源 → color 内无拥塞；拥塞只在 color 之间（共享物理通道）
  • 仲裁：round-robin 或 priority（color 0–7 高优先级）
  • 反压：每 color × 每方向独立 Stall 信号，沿路由反向传播
  • Input Qs 897：每 fabric/local color 一个虚拟队列
  • wavelet 写入 → Active Bit 置位（或 activate 指令 / DSD.AC / 环形缓冲 push-pop）
  • Picker：选 active 且未 block 的 color → addr = base + color×4 → 取指执行
  • block/unblock 指令门控：被 block 的 color 不参与选取

软件管「空间」：编译期映射通信图 → 静态多播路由 + color 划分 + 无环校验。

硬件管「时间」：运行期 ready 仲裁 + 激活/阻塞触发任务。软件不在运行时切路由，只影响哪些 color 此刻就绪。
