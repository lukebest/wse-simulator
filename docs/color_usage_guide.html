核心结论：TDM 还是 Trigger？

不是 TDM；是「常驻多色 + 三种触发」。

没有全局时隙表，也没有「全芯片同一时刻只有一条 color」。链路上是 就绪色按需统计复用（L1）；计算上是 wavelet 事件触发 task（L2）；单条 color 的路由可由 control wavelet 在预设相位间切换（L3）。

对你问题的精确回答：

  1. 「TDM 轮转时分？」→ 否。L1 是就绪色统计复用，非固定 slot。
  2. 「需要 trigger 切换虚拟子网？」→ 部分是：L2 触发 任务（不切换 color）；L3 才是字面意义的「trigger 切换 VN」——切的是 同一条 color ID 内部 的 ≤4 套编译期预设路由拓扑，不是在不同 color 间切换。

三层机制概览

  • 每 color：独立 Data Queue（默认 2 entries/color）+ 静态 Dest 661 多播表
  • 每 color 单活跃输入源（SDK：多 rx 同时收 → undefined）→ color 内无拥塞
  • 拥塞只在 color 之间：共享物理通道 → Router Sched RR/priority 仲裁 ready colors
  • 反压：每 color × 每方向独立 Stall，沿路由反向传播
  • Input Qs：每 fabric color 一个虚拟队列（WSE-3 经 @initialize_queue 绑定）
  • wavelet 写入 → Active Bit；task 可调度当且仅当 activated and unblocked（SDK WTT）
  • Picker：选 active 且未 block 的 color → addr = base + color×4 → 取指执行
  • @activate / @block / @unblock：软件精确门控触发时机
  • 编译期：@set_color_config 为每条 color 预置 pos0（初始 rx/tx）+ pos1/pos2/pos3
  • 运行期：route-switching control wavelet 按序推进路由相位（非时钟、非数据 wavelet）
  • ring_mode=true：pos3 后回绕 pos0 → 适合 allreduce RS/AG、双向环方向交替
  • pop_mode：控制 wavelet 指令序列随 PE 经过而消耗
  • WSE-3 限制：仅 color {0–9,12,13,16,17,20,21} 支持 switch

软件管「空间 + 预案」：CSL layout 映射通信图 → 静态多播路由、color 划分、每 color ≤4 套路由相位预案、filter / 优先级。

硬件管「时间」：L1 ready 仲裁 + L2 wavelet 激活/阻塞触发 task + L3 control wavelet 推进路由相位。

运行期 唯一 的路由变化是 L3 在编译期预置的 pos0–pos3 间切换——仍属「无动态路由计算」，与专利 "no dynamic routing decisions" 不矛盾。
