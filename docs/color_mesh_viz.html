流量感知的calendar集合通信逐周期可视化

本页展示 Color 虚拟网络（VN） 机制下的 2D Mesh 集合通信调度，与 collective-mesh-viz.html 的逻辑 butterfly / tree / ring 算法视图互补。 理论背景见 time-expanded graph.md §9 与 无冲突集合通信综合报告。 每条端到端流分配独立 color（时分虚拟网）。节点 router 同时具备 多播 / fan-out（一入边复制到多出边）与 inline-reduce / fan-in（多入边归约后转发），边-时隙仍无冲突（每有向边每 slot ≤1 flit）。 默认构造：Broadcast/Reduce 行列多播树（Z=ecc(r)）； AllReduce 双向维累加（Z=D=X+Y−2，达下界）； AllGather/Gather Hamilton 环（偶数列 mesh，Z=⌈(N−1)/2⌉, stall=0）； All-to-all 默认单相 rigid-XY（无 stage / 无 PE 中继, stall=0, peak=1, Z≈z*，实测 17/134/791 @ 4×4/8×8/12×16），可切「二相维序」（Z≈2z*）或贪心 XY 基线对照； 可选 Dim-wise XY/RHD。达界方法 4×4 示意见下方「算法思路与流程」第 5 节，与 报告 §2.5 一致。 三种时隙表尺度需区分：静态转发规则周期 P_min=1（环/树/维扫规则逐拍不变）、一次性 makespan Z、每边色重数 L*（≠周期）。 calendar 用 源端口→目的端口 表示连接。 调度基线为 T=1（无 router 缓冲）；预分配时隙构造（Hamilton / 维累加）可直接零 stall 验证。 节点 index：node = row×cols + col，显示 (x,y) 为列、行。

指标说明：Makespan = 第一个 flit 注入 NoC 的 cycle 到最后一个 flit 到达目的 PE 的 cycle 之差（末包到达 − 首包发出）；时间轴上界 lastArrival 为末包到达时刻。Peak edge sharing 恒为 1（calendar 调度无冲突）；源端等待为数据滞留 home PE 的总拍数（不计进出惩罚）；PE 暂存次数/惩罚为中间落 PE 的次数与累计 10-cycle 进出代价（仅 pe 策略 > 0）。下表对比三种 relay 策略，▶ 为当前所选。

算法思路与流程（约束模型 · 两种 relay 策略 · 各集合通信，含 all-to-all）

1. 网络与约束模型

  • 拓扑：rows×cols 2D Mesh，每个节点含一个 router + 一个本地 PE（core）。路由固定为 XY 维序（先沿 X 后沿 Y），每跳占 1 cycle。
  • 无 router 缓冲（T=1 刚性中继）：cycle t 进入某 router 的 flit 必须在 t+1 从出口发出，router 内不排队。冲突资源是 (有向边, cycle)：同一物理有向边在同一 cycle 至多 1 个 flit。
  • 新增 PE 进出惩罚：数据“进入 PE 再出 PE”需 PE_INOUT_LATENCY = 10 cycle。因此一旦把流经的数据暂存到中间 PE，就要付 10-cycle 进出代价；若不进 PE，则数据必须持续在 NoC 上流转，可能与其他流争用边而产生冲突。
  • 源端 / 终点：源数据本就驻留在 home PE，注入（出 PE）前的等待只是“延迟出口”，不重复计 10-cycle 惩罚；终点入 PE 是消费端，不另计。10-cycle 惩罚专门刻画中间节点的暂存（enter+exit）。

2. 三种 relay 策略（权衡）

  • noc（NoC 无缓冲，仅源端等待）：为每条流寻找一个注入时刻，使整条 XY 路径在 +1/跳 下逐边无冲突；做不到就让数据继续在 home PE 等待（PE:wait）后重试。优点：永不付 10-cycle 进出惩罚、端到端=跳数；代价：拥塞模式（如 all-to-all）源端等待累积、makespan 拉长。
  • pe（PE 暂存）：贪心地优先走 +1 刚性中继；当下一跳边在 t+1 被占用时，把 flit 落入当前节点 PE（→PE），保持 PE:buf 至少 10 cycle，再在 ≥ 到达+10 的最早空闲 slot 重新注入下一跳。优点：化解 NoC 边冲突、降低源端反压；代价：每次暂存 +10 cycle 端到端延迟。
  • defl（NoC 偏转 / hot-potato）：flit 从不因中途拥塞而落入 PE，每个 cycle 必须离开 router。优先选一条空闲且缩短曼哈顿距离的边（productive），若都被占用则偏转到任一空闲边（misroute，尽量不立刻折返），停留在 NoC 上绕行；之后从新节点重新朝目的地路由。优点：中途无 10-cycle 进出惩罚（PE:buf=0）、源端反压小；代价：路径不再是最短 XY，额外 hop 增加端到端延迟，重载下可能游走。若某 cycle 四向出口全被占用（罕见死点），则推迟注入重试。

注意 defl 的边界：defl 只消除“中途遇阻落 PE”这一项（中途 PE:buf 恒为 0）。它不消除两类与路由策略无关的 PE 驻留：(1) 源端等待 PE:wait（注入前数据停在 home PE，不计进出惩罚，所有策略都有）；(2) X→Y 维度切换的 10-cycle 进出——All-gather/All-reduce 的换维累积本就发生在 PE 内（X 收完落 PE、Y 再从 PE 发出），属于集合算法本身，对 noc/pe/defl 三种策略一律生效。因此选 defl 时，allgather 仍会在 X→Y 处看到一次 PE 进出（这不是中途暂存）。

3. 调度流程（一次性日历）

  1. 按 (release, 路径长度, colorId) 排序所有流，逐流贪心放置，维护全局 reserved=(edgeId,cycle) 占用集合。
  2. 对每条流的每个 flit：
    noc：从 max(release+stall, 上个flit首边+1) 找首边最早空闲 slot 注入，再验证后续每跳 +1 是否空闲；若任一跳冲突则 stall++ 重试。
    pe：注入后逐跳判断——空闲则 +1 刚性中继；被占用则落 PE 暂存（到达+10 起找最早空闲 slot）。
    defl：注入后逐 cycle 选边——优先空闲的 productive 边，否则偏转到任一空闲边；动态生成实际边序列（非固定 XY），死点则推迟注入重试。
  3. 把选定的 (边, cycle) 写入 reserved 并记录 calendar：源端 PE:wait→PE→dir；中间刚性/偏转 src→dst（偏转可出现折返如 E→W）；中间暂存 src→PE … PE:buf … PE→dst。
  4. 统计 makespan（首包注入 → 末包到达）、源端等待、PE 暂存次数与进出惩罚，并与三种 relay 策略并排对比。

4. 各集合通信的生成思路（与综合报告一致）

  • Broadcast / Reduce：行列多播树（fan-out / inline-reduce），z*=ecc(r)（root 离心率 = 到最远节点曼哈顿跳数），预分配 stall=0；静态转发规则 P_min=1，一次性 Z=ecc。
  • AllReduce（默认：维累加）：X/Y 双向扫边，每 slot 全 mesh 并行，Z=D=X+Y−2，规则 P_min=1，无 PE 换维惩罚。可选 Dim-wise RHD 对照（含 X→Y +10 cycle）。
  • AllGather（默认：Hamilton 环）：偶数列 mesh 上 snake 哈密顿环 + CW/CCW 双向流水线，Z=⌈(N−1)/2⌉，stall=0；作为色无关静态环转发规则 P_min=1，而 L*=⌈(N−1)/2⌉ 是色表深度=makespan（≠规则周期）。可选 Dim-wise RHD。
  • Gather（默认：Hamilton→根）：环上每源选短弧到 root，Z=⌈(N−1)/2⌉，下界 ⌈(N−1)/deg(r)⌉（deg(r)=root 邻接链路数：角 2/边 3/内 4），规则 P_min=1。可选 XY incast。
  • All-to-all（两种 variant）：z*=max(N·cols/4, N·rows/4)（bisection 下界）。
    • 二相 stall=0（默认）：二相维序（行内→PE 中继→列内）+ 区间着色，预分配 slot ⇒ peak=1, stall=0，实测 Z=44/272/1366 @ 4×4/8×8/12×16（≈2·z*）。
    • 贪心 XY 基线：全置换 XY 单播 + 在线调度，链路 peak=1 但源端等待 stall>0，makespan 更接近 z*。
    取舍：零等待 vs 短 makespan。详见报告 §5.1。
  • Router 时隙表三尺度：静态转发规则周期 P_min=1（结构化构造普适）；一次性深度 Z_router=makespan；每边色重数 L*（每源独立 color 时的边负载，≠规则周期）。

5. 达界方法 4×4 示意（选 All-reduce / All-to-all 的 optimal variant 可逐周期复现）

5.1 AllReduce → z*=D=X+Y−2：双向维累加（buildDimaccumAllreduceFlows）。下界 = 直径：一个角点的结果必须吸收对角点的数据，至少 D 跳。构造分两相，每相是各行/列上同拍并行的一维双向扫描——东行波携带前缀和、西行波携带后缀和，两波走相反方向的有向边，永不冲突；每节点 inline-reduce「前缀 + 自身 + 后缀」=该维度全和。

5.2 AllToAll → z*=max(N·cols/4, N·rows/4)：二相维序 + 区间着色（buildAllToAllTwophaseFlows）。下界 = 对剖负载：竖切左右各半，(N/2)²=N²/4 条消息穿过 rows 条切边 ⇒ 每边 ≥ N·cols/4 拍。

5.3 AllToAll → 单相 rigid-XY 日历（无 stage、无 PE 中继，Z≈z*，本页默认）（buildAllToAllSinglePhaseFlows）。分 stage 不是必须的。 关键观察：水平边只承载 X 段、垂直边只承载 Y 段（两类资源互不相交），所以一条消息可以在转角 router 内刚性直转（每跳 +1，不弹出 PE、不设屏障）。于是每条消息只需一个注入相位 φ：整条 L 形 XY 路径上第 h 跳占用 slot φ+h。按最长路径优先（decreasing first-fit / LPT）放置——角到角的长路径恰好穿过最拥塞的对剖边，先把它们排满，再用短路径填空隙——即可让每条有向边每拍 ≤1 flit。

  • 无 stage / 无 PE 中继：没有 X→Y 屏障、没有 10-cycle 进出代价，转角在 router 内完成（XY 维序天然如此）。
  • 预分配 ⇒ stall=0, peak=1：φ 是日历的一部分（非在线源端等待）。
  • 实测 makespan（最长优先 first-fit）：Z = 17 / 134 / 791 @ 4×4 / 8×8 / 12×16，即 ≈1.06× / 1.05× / 1.03× z*——几乎贴住对剖下界，远优于二相的 2.75×。
  • 代价：没有闭式相位，φ 由离线贪心 first-fit（多项式、确定性）求得；二相则有闭式区间着色。两者都 peak=1、stall=0、无中间 PER。

为什么树/环不行？ 对剖下界 z*=max(N·cols/4, N·rows/4) 对任何方法都成立（N²/4 条消息必过切边）。要达界必须用满所有切边。基于单棵树或单条 Hamilton 环的 all-to-all 把流量挤到少数链路上，远不能填满对剖带宽，因而更慢（树/环更适合 broadcast/reduce 这类一对多）。真正的杠杆不是换拓扑，而是去掉 stage 串行化：单相 rigid-XY 在维序网络上即可同时跑满横、纵两类边。
