Color VN 集合通信逐周期可视化

本页展示 Color 虚拟网络（VN） 机制下的 2D Mesh 集合通信调度，与 collective-mesh-viz.html 的逻辑 butterfly / tree / ring 算法视图互补。 每条端到端流分配独立 color（时分虚拟网，数量不限）；路径为固定 XY 维序路由。 每个 router 具备 多播：calendar 用 源端口→目的端口（E/W/S/N 为 router 四向端口，非行进方向）表示连接（如 W→E 西口入东口出、W→E+S 西口入东/南口出、PE→E 本地注入东口）；等待仅在源端以 PE:wait 表示。每 hop 占 1 cycle，每个节点每个 cycle 更新四向端口状态。 集合通信前为各 router 预配置 color calendar；全局调度保证同一 cycle 同一物理 edge 至多一个 flit。 Broadcast 用行/列多播树（共享 color bus）；Gather 为每 PE 向 root 的 XY 流；Reduce 为 2D 树：先列内逐级归约到 root 行，再行内到 root（每跳单周期，中间节点本地 reduce，非全量汇聚到 root）； All-reduce 为维度序 RHD：先横向（X）再纵向（Y）递归减半/加倍交换（与 collective-mesh-viz dim-wise exchange 一致），非树归约+多播。 All-gather 为维度序 RHD（X/Y stride 从大到小），每阶段 flit 数随已收集块数倍增，使每 PE 最终持有全体 rows×cols 份数据块。 All-to-all 为全置换：每个 PE 向其余每个 PE 各发一条独立消息（共 N×(N-1) 条 VN 流，XY 路由），是对分对剖带宽压力最大的模式。 调度基线为 T=1（无 router 缓冲）：任意 router 在 cycle t 入口的数据必须在 t+1 从出口发出，中间 router 不缓冲。 新增约束：数据进出 PE 需 10 cycle。三种 Relay 策略：noc（阻塞时仅在源端 home PE 等待注入 PE:wait，永不付进出惩罚）；pe（阻塞时落入当前 PE 暂存 →PE/PE:buf，付 +10 cycle 进出代价后再注入）；defl（NoC 偏转/hot-potato：不进 PE，被阻塞时改走其它空闲口绕行，多走 hop 但无进出惩罚）。 节点 index：node = row×cols + col，显示 (x,y) 为列、行。

指标说明：Makespan 为最后 flit 占用最后一条 edge 的 cycle+1；Peak edge sharing 恒为 1（calendar 调度无冲突）；源端等待为数据滞留 home PE 的总拍数（不计进出惩罚）；PE 暂存次数/惩罚为中间落 PE 的次数与累计 10-cycle 进出代价（仅 pe 策略 > 0）。下表对比两种 relay 策略，▶ 为当前所选。

算法思路与流程（约束模型 · 两种 relay 策略 · 各集合通信，含 all-to-all）

1. 网络与约束模型

  • 拓扑：rows×cols 2D Mesh，每个节点含一个 router + 一个本地 PE（core）。路由固定为 XY 维序（先沿 X 后沿 Y），每跳占 1 cycle。
  • 无 router 缓冲（T=1 刚性中继）：cycle t 进入某 router 的 flit 必须在 t+1 从出口发出，router 内不排队。冲突资源是 (有向边, cycle)：同一物理有向边在同一 cycle 至多 1 个 flit。
  • 新增 PE 进出惩罚：数据“进入 PE 再出 PE”需 PE_INOUT_LATENCY = 10 cycle。因此一旦把流经的数据暂存到中间 PE，就要付 10-cycle 进出代价；若不进 PE，则数据必须持续在 NoC 上流转，可能与其他流争用边而产生冲突。
  • 源端 / 终点：源数据本就驻留在 home PE，注入（出 PE）前的等待只是“延迟出口”，不重复计 10-cycle 惩罚；终点入 PE 是消费端，不另计。10-cycle 惩罚专门刻画中间节点的暂存（enter+exit）。

2. 三种 relay 策略（权衡）

  • noc（NoC 无缓冲，仅源端等待）：为每条流寻找一个注入时刻，使整条 XY 路径在 +1/跳 下逐边无冲突；做不到就让数据继续在 home PE 等待（PE:wait）后重试。优点：永不付 10-cycle 进出惩罚、端到端=跳数；代价：拥塞模式（如 all-to-all）源端等待累积、makespan 拉长。
  • pe（PE 暂存）：贪心地优先走 +1 刚性中继；当下一跳边在 t+1 被占用时，把 flit 落入当前节点 PE（→PE），保持 PE:buf 至少 10 cycle，再在 ≥ 到达+10 的最早空闲 slot 重新注入下一跳。优点：化解 NoC 边冲突、降低源端反压；代价：每次暂存 +10 cycle 端到端延迟。
  • defl（NoC 偏转 / hot-potato）：flit 从不进入中间 PE，每个 cycle 必须离开 router。优先选一条空闲且缩短曼哈顿距离的边（productive），若都被占用则偏转到任一空闲边（misroute，尽量不立刻折返），停留在 NoC 上绕行；之后从新节点重新朝目的地路由。优点：无 10-cycle 进出惩罚、源端等待小；代价：路径不再是最短 XY，额外 hop 增加端到端延迟，重载下可能游走。若某 cycle 四向出口全被占用（罕见死点），则推迟注入重试。

3. 调度流程（一次性日历）

  1. 按 (release, 路径长度, colorId) 排序所有流，逐流贪心放置，维护全局 reserved=(edgeId,cycle) 占用集合。
  2. 对每条流的每个 flit：
    noc：从 max(release+stall, 上个flit首边+1) 找首边最早空闲 slot 注入，再验证后续每跳 +1 是否空闲；若任一跳冲突则 stall++ 重试。
    pe：注入后逐跳判断——空闲则 +1 刚性中继；被占用则落 PE 暂存（到达+10 起找最早空闲 slot）。
    defl：注入后逐 cycle 选边——优先空闲的 productive 边，否则偏转到任一空闲边；动态生成实际边序列（非固定 XY），死点则推迟注入重试。
  3. 把选定的 (边, cycle) 写入 reserved 并记录 calendar：源端 PE:wait→PE→dir；中间刚性/偏转 src→dst（偏转可出现折返如 E→W）；中间暂存 src→PE … PE:buf … PE→dst。
  4. 统计 makespan、源端等待、PE 暂存次数与进出惩罚，并与另一策略并排对比。

4. 各集合通信的生成思路

  • Broadcast：root 经行/列多播树（共享 color bus，一次 src→E+S 分叉）覆盖全网，最小化边占用。
  • Gather：每个 PE 沿 XY 把数据汇聚到 root（incast），root 邻边为瓶颈（L* 偏大）。
  • Reduce：2D 归约树——先列内逐级归约到 root 所在行，再行内归约到 root；中间节点本地做 reduce，非全量汇聚。
  • All-reduce：维度序递归减半/加倍（RHD），先 X 后 Y 逐维交换，等价 reduce-scatter + all-gather，无单点 incast。
  • All-gather：维度序 RHD（stride 由大到小），每阶段 flit 数随已收集块数倍增，最终每 PE 持有全部 rows×cols 块。
  • 维度切换的 PE 进出惩罚：All-reduce / All-gather 的 X 阶段与 Y 阶段是各自独立的 VN 流，仅在物理 PE 处相接——X 阶段的数据到达后进入该 PE 暂存，再由 Y 阶段从同一 PE 重新注入，这正是一次“进 PE 再出 PE”。因此在 X→Y 维度切换处，Y 阶段的 release 额外 +PE_INOUT_LATENCY (10) cycle。同维度内连续 stride 的过渡只算传输时间（假设可在 router 内流水、不重新完整进出 PE），不计该惩罚。
  • All-to-all：全置换，N×(N-1) 条独立 VN 流（每个有序 (src,dst) 一条），XY 路由。这是对分带宽压力最大的模式：中央列/行边被大量流穿越，L* 最高。
    在 noc 下表现为大量源端等待错峰注入；pe 用中间 PE 暂存吸收边冲突、缩短源端反压，但累计 10-cycle 进出惩罚；defl 则让被阻塞的 flit 在 NoC 上偏转绕行、用额外 hop 换取更小的源端等待与零进出惩罚——三种策略的 makespan/延迟权衡在对比表中一目了然。周期模式对 all-to-all 无刚性 T=1 解，故流数超阈值时跳过相位回溯。
